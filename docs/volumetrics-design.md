# Sky, atmosphere, clouds and volumetric fog for true-sim: design and staged plan

Status: proposal, 2026-11-05. Covers engine issues #418 (sky, atmosphere, volumetric clouds) and #419 (volumetric fog
and lighting). Engine read at `origin/main` 83220a7 (`SkyBackground`, `Environment`, `EnvironmentLighting`,
`ClusteredLights`, GPU particles, `MotionVectors`, `Denoiser`, `ReferencePathTracer`, `ProbeVolume`, shadows being
rebuilt as data in #120). Nothing here is built.

Costs from papers and other engines are what their authors report on their hardware and are marked as such. Costs for
this engine are **estimates** (marked "est.") scaled from those figures and from the GI design's measurements on the
RX 9070 XT. Each technique has to earn its place in a benchmark under the standing rules: only correct techniques, one
frame of latency allowed, trade-offs as settings with `off`, every tunable a setting, nothing allocated per frame, no
libraries beyond the JDK and LWJGL, XR must work.

---

## 0. Summary

- **One media model, four consumers.** A single Slang module (`media.slang`) defines the participating media
  everywhere: atmosphere (Rayleigh, Mie, ozone), height fog, local fog volumes, particle-injected smoke and dust, and
  clouds. It also holds the phase functions, the energy-conserving segment integration and the multiple-scattering
  approximation. The sky LUTs, the froxel fog, the cloud marcher and the **reference path tracer** all call it. That is
  what makes "compare against the reference" meaningful.
- **Atmosphere: Hillaire 2020.** Transmittance, multiple-scattering and sky-view LUTs plus an aerial-perspective froxel
  volume. It is cheap and resolution-independent, works at any altitude (airplane, orbit), and was validated against a
  path tracer by its author. The atmosphere drives the sun and moon colours, and a time-sliced **sky capture** (sky
  plus clouds into a cube). That cube feeds the existing `Environment` filtering, so environment lighting, GI miss
  rays and reflections see the real sky. Bruneton 2008 is kept only as a second reference.
- **Clouds: two representations, one shading model.**
  - **Layered (2.5D) procedural** clouds, as in Nubis 2015–2017 and Hillaire 2016. A game-settable weather map
    (coverage, type, darkness, top height) plus per-type vertical profiles cover every cloud type: cumulus,
    cumulonimbus with anvils, stratus and stratocumulus, altostratus. Cirrus is a separate thin high layer. Noise
    textures are generated by our own compute shaders at startup.
  - A **camera-centred voxel cache** (Nubis Cubed, 2023) for fly-through. The procedural model, plus optional authored
    voxel "stamps" for hero storms, is baked into a clipmap of density-profile, signed-distance and sun-optical-depth
    volumes. It is refreshed incrementally, gives empty-space skipping and cheap lighting near and inside clouds, and
    removes the layer-shell artefacts.
- **Cloud lighting:**
  - single scattering with the Jendersie–d'Eon fog/cloud phase function (HG + Draine);
  - Wrenninge's octaves for multiple scattering, with parameters **fitted to our path tracer** rather than tuned by eye;
  - ambient from the sky SH, attenuated by an optical-depth estimate;
  - a Beer shadow map (Hillaire 2020) for cloud shadows on the ground, in fog and in the atmosphere, handed to #120 as
    the sun's transmittance;
  - lightning as a short-lived emitter inside the volume, with a diffusion falloff, and also as an ordinary engine
    light.
- **Cloud rendering:** ray march from the camera (near) or from the layer shell (far), with blue-noise jitter, at
  quarter resolution (half by half) plus temporal reprojection on the clouds' own depth. The 1/16-pixels-per-frame
  scheme (Schneider 2015) and full resolution are settings to benchmark.
  - **XR:** far clouds are rendered once from the head centre and resampled per eye. Disparity is below 0.1 px beyond
    about 1 km. Near clouds and inside-cloud segments are rendered per eye.
- **Volumetric fog: froxels** (Wronski 2014, Hillaire 2015, Unreal, Godot):
  - media injection: height fog, local volumes, particles;
  - lighting by every light through `ClusteredLights` and #120's shadows. Ray-traced-shadow lights get a stochastic
    ray query per froxel;
  - ambient from the GI probe volume and the sky;
  - temporal reprojection, then front-to-back integration;
  - opaque surfaces, transparents and particles read the result with one lookup.

  A **ray-marched high-quality** mode (per pixel at half resolution, sharp beams, ray-traced shadows) and an
  **epipolar** sun-shaft fallback are the alternatives. Screen-space radial blur is not a correct technique and is a
  question for the user (§12).
- **Validation:** the reference path tracer gains participating media: delta and ratio tracking with a majorant grid,
  the spherical atmosphere, clouds from the same density function, and local media. Closed-form tests (transmittance,
  phase normalisation, slab single scattering, media furnace) gate each stage. Image comparisons with region error
  budgets gate each technique. The Wrenninge parameters and the ambient model are fitted to the path tracer, per cloud
  type.
- **Budget targets (est., RX 9070 XT):**

  | Setting | Atmosphere | Clouds | Froxel fog |
  |---|---|---|---|
  | 1080p | ≤ 0.15 ms | 0.6–1.5 ms (2–4 ms inside a storm) | 0.3–0.8 ms |
  | 4K | ≤ 0.25 ms | 1.5–3.5 ms | 0.6–1.5 ms |

  XR adds well under 2× for clouds (shared far field) and about 2× for fog (per eye).

### 1.1 Frame placement (proposal)

```
 frame start
  ├─ [frame] Atmosphere: transmittance + multi-scattering LUTs (only when the atmosphere's parameters change)
  ├─ [frame] Weather: weather map update (game writes / wind advection), cloud voxel cache refresh (budgeted, async)
  ├─ [frame] CloudShadow: Beer shadow map from the sun (time-sliced, async)
  ├─ [frame] SkyCapture: cube from sky-view + clouds, 1 face or 1 cloud slice per frame -> Environment filter
  ├─ [view]  sky-view LUT + aerial-perspective volume (per view; eyes share the sky-view LUT, the AP volume is per eye)
  ├─ [view]  Froxel fog: inject -> light -> temporal -> integrate (async allowed, overlaps the depth/geometry passes)
  ├─ [view]  opaque shading (forward or visibility buffer): sun * cloud transmittance * shadow; probes; ...
  ├─ [view]  at Anchor.OPAQUE, in order:
  │     Sky (atmosphere sky-view, sun/moon) on depth-0 pixels
  │     Clouds: march (quarter res) -> temporal -> upsample + composite (with AP at the cloud depth)
  │     Fog apply: froxel in-scatter/transmittance on opaque pixels (or merged into AP apply)
  │     (AO / GI composites / SSR exist before or after as their design says; fog applies last)
  ├─ [view]  TRANSPARENT: blended surfaces and particles read froxel fog + AP + cloud transmittance at their depth
  └─ POST (TAA #403, bloom), TONE_MAP, UI
```

**Ordering rule.** The participating media between the camera and an opaque surface is applied once, by one pass,
after every surface term. AO, GI and SSR composites must never see fogged colour, or they would fog twice.
Transparents apply media in their own shader.

## 2. The shared media model (`media.slang`)

- **Coefficients.** Scattering σs (RGB) and absorption σa (RGB), so extinction σt = σs + σa. Emission Le (RGB). A
  phase descriptor (kind + parameters). All in SI units (1/m). The atmosphere works in km internally for precision and
  converts at the boundary.
- **Phase functions** (each normalised; each with a sampling routine for the path tracer):
  - **Rayleigh** `3/(16π)(1+cos²θ)`.
  - **Cornette–Shanks** for atmospheric Mie, as Bruneton and Hillaire use.
  - **Henyey–Greenstein**, and a **dual-lobe HG** (forward g₁, backward g₂, blend w), as Frostbite and UE use for clouds.
  - **Draine**, and the **Jendersie–d'Eon 2023 HG + Draine fit** parameterised by water-droplet diameter d. The paper
    reports it matching the Mie phase function of fog and cloud droplets over roughly 5–50 µm, with analytic sampling.
    This is the default for clouds and water fog: one parameter (droplet size) replaces three arbitrary ones and stays
    correct.
  - Optional **tabulated Mie** (1D LUT from our own Lorenz–Mie code, run offline in Java), for single scattering only,
    to get fogbows and glories. Hillaire 2020 suggests this split; it is a setting.
- **Segment integration:** Hillaire 2015's energy-conserving form `S_int = (S − S·e^{−σt·Δ}) / σt`. It is exact for
  constant S over the step and stable at high density, unlike rectangle or trapezoid integration. The variant with a
  linearly interpolated shadow (Hillaire 2020) is noted as unstable by its author and is not used.
- **Multiple scattering for dense media** (clouds): Wrenninge's octaves (Wrenninge 2013; Wrenninge et al. 2017 course).
  It sums N octaves of single scattering, octave i using σs·aⁱ, σt·bⁱ and phase g·cⁱ, with a ≤ b for energy
  conservation. Frostbite (2016) and UE (2020) ship 2–3 octaves. We fit (a, b, c, N) to the path tracer per droplet
  size and density range (§10.3). Fitted, the method is a validated approximation rather than a tuning knob.
- **Atmosphere media:**
  - Rayleigh: exponential density, 8 km scale height;
  - Mie: exponential density, 1.2 km scale height, absorption ratio;
  - ozone: tent profile around 25 km;
  - all parameters are settings, as in Hillaire 2020 (Earth defaults, Mars-like presets possible).
- **Height fog:** exponential in altitude, with an analytic integral along a ray (Wronski 2014; the Unreal exponential
  height fog). It is used beyond the froxel range and in the cheap fallback.

## 3. Atmosphere (LUTs) — #418

**Chosen: Hillaire 2020** ("A Scalable and Production Ready Sky and Atmosphere Rendering Technique", EGSR 2020;
reference implementation `sebh/UnrealEngineSkyAtmosphere`).

| LUT | Size (paper) | Content | When |
|---|---|---|---|
| Transmittance | 256×64 RGBA16F | sun transmittance from (altitude, sun zenith) | on parameter change |
| Multiple scattering | 32×32 RGBA16F | infinite-order isotropic multiple-scattering factor Ψ_ms (geometric series of second order) | on parameter change |
| Sky-view | 192×108 RG11B10/RGBA16F, non-linear latitude mapping that packs detail near the horizon | in-scatter for every direction from the camera position | per frame, per view position |
| Aerial perspective | 32×32×32 froxels (in-scatter RGB + transmittance) over ~32 km | in-scatter and transmittance from the camera to depth | per frame, per eye |

- **Why this one.** The author's comparison against a volume path tracer shows it as close as Bruneton 2008. It also
  handles denser atmospheres and every altitude, from the ground to space, which a flight sim needs. It needs no 4D
  LUT, so there are no horizon artefacts from LUT parameterisation. Changing the time of day or the atmosphere costs
  only one LUT rebuild.
- **Reported cost** (Hillaire 2020 SIGGRAPH course slides, GTX 1080):
  - sky and atmosphere rendered at 720p: 0.14 ms;
  - total with LUTs: 0.31 ms;
  - the mobile column of the same slide lists 1.03 ms for the LUTs (read from the slide text; the table itself is an
    image).
- **Est. here:** ≤ 0.1 ms for the LUTs plus about 0.05 ms per 1080p view for applying the sky-view LUT. At 4K the
  apply roughly doubles. Total ≤ 0.25 ms.
- **Per-pixel option** (setting `render.sky.atmosphere.perPixel`): ray-march the sky per pixel instead of reading the
  sky-view LUT. It is the paper's "high quality" path, needed for volumetric cloud shadows in the sky (§7.3) and as a
  reference in tests.
- **Sun and moon:**
  - Sun disc with limb darkening, angular radius a setting (0.2725°). Its colour is the transmittance at the observer
    (one LUT fetch).
  - The sun's light colour for shading is the transmittance from the shading point, as Hillaire 2020 recommends for
    large worlds. For small scenes it is evaluated once per frame at the camera; a setting.
  - The moon is a second directional light: albedo, a phase-of-moon term (Lommel–Seeliger or a simple Lambert sphere)
    and the same transmittance.
  - Stars and airglow are user questions (§12).
- **Planet curvature:**
  - the planet radius is a setting (6,360 km), with origin rebasing aware of altitude above it;
  - the ground albedo for multiple scattering is a setting;
  - the ground below the horizon shows the planet (for high altitude), or the scene's terrain.
- **Alternatives (benchmarked or reference only):**
  - **Bruneton & Neyret 2008** (and Bruneton's 2017 rewrite): 4D scattering LUT, multiple orders, precomputed. Ported
    from the paper (no code taken) as a *second reference* in tests, not a runtime kind: it is more memory and
    precompute, with known horizon artefacts.
  - **Prague sky model** (Wilkie et al., SIGGRAPH 2021): a fitted spectral model up to 15 km altitude. A third
    reference for the ground-level sky colour, if its data files may be used (licence to check). Otherwise skip it.
  - **Spectral** rendering with more than RGB wavelengths: a question (§12). RGB with three representative wavelengths
    is the default; the reference path tracer can be spectral and shows the error.

## 4. Aerial perspective

- The **AP froxel volume** from §3 (32×32×32 per eye) applies to everything distant: opaque pixels beyond the fog range,
  clouds (at their transmittance-weighted depth), transparents and particles. It is sampled with one trilinear fetch.
- **Near the camera**, the froxel fog (§8) holds the same atmosphere media in its own (finer) grid. The fog's integrated
  result over [0, fogFar] is combined with the AP result over [fogFar, depth] by re-basing the AP integral at fogFar.
  This is exact: the two integrals are of the same media, split at one depth. There is then one atmosphere, no double
  counting, and a continuous transition.
- **Cloud shadows in the atmosphere** (light shafts at kilometre scale) are optional. The AP and sky-view passes sample
  the cloud Beer shadow map per sample. Hillaire 2020 calls this the "fast" path stored in the LUTs; the per-pixel path
  is the high-quality one.
- **Cost:** < 0.05 ms per eye (est.). The volume is 32 K froxels.

## 5. Cloud modelling — #418

### 5.1 Weather map (game-settable, changes over time)

- **What it is.** A 2D texture, RGBA16F, 512² by default (a setting), centred on the camera and scrolled in texel steps
  (toroidal addressing) over a world extent that is a setting (64 km default; 150 km for flight). Channels:
  - R: coverage 0–1;
  - G: cloud type 0–1 (indexes the profile atlas, §5.2);
  - B: darkness and precipitation, which drives density scale, droplet size and the storm interior's absorption;
  - A: top-height override (towering cumulus and cumulonimbus heights vary per cell).
- **Sources, composited by a compute pass each frame:**
  - the game's own layers: painted maps, or `WeatherBrush` stamps (position, radius, type, coverage, strength,
    velocity) for "storm rolling in";
  - a procedural base from the weather preset (noise-driven coverage, Schneider 2015 style);
  - wind advection.
- **Weather presets with transitions:** clear, fair cumulus, scattered cumulus, broken, overcast stratus, altostratus,
  storm. A transition blends the parameters over time. The time scale and how clouds evolve are questions (§12).
- **Second map at low resolution** for a range far beyond the high-resolution map (to the horizon from altitude):
  128² over 400 km, coverage and type only. Clouds near the horizon at 10 km altitude are 300+ km away.

### 5.2 Cloud types via vertical profiles

- **Mechanism:** Schneider 2015 and 2017 (height gradients per type), refined by Nubis Evolved (2022, a "dimensional
  profile"). A **profile atlas** (2D texture: type × normalised height in the layer) gives:
  - base and top altitudes;
  - the density gradient;
  - the erosion balance (billowy vs wispy detail);
  - a wind-shear and anvil spread factor;
  - the detail-noise scale;
  - droplet diameter (phase);
  - absorption (storm darkness).
- **Density:** `density = profile(type, h) × coverage-remap(baseShape, coverage) − erosion(detail, profile)`, as in
  Schneider 2015 and 2017, with the anvil handled by the profile widening the coverage near the top and skewing along
  the wind.

| Type | Altitude (default, settings) | Profile | Notes |
|---|---|---|---|
| Stratus / fog bank | 0–600 m | flat slab, soft top, low erosion | can touch the ground: merges into froxel fog near the camera |
| Stratocumulus | 500–2,000 m | slab with lumpy top, medium coverage | |
| Cumulus (fair weather) | 800–2,500 m base, tops ≤ 3 km | rounded base cut, billowy top | flat bases come from the profile's sharp base |
| Towering cumulus | 800–6,000 m | tall, billowy | |
| Cumulonimbus with anvil | 800–12,000 m | tall core, top widened and sheared by the wind; dark, large droplets below | darkness via the weather map's B channel; lightning hosts (§6.5) |
| Altostratus / altocumulus | 2–6 km | thin layer, wavy (curl-distorted) | |
| Nimbostratus / overcast | 0.5–4 km | thick, uniform, high coverage | rain shafts: question (§12) |
| Cirrus / cirrostratus | 7–12 km | separate thin layer (§5.4) | ice crystals: a different phase (HG g≈0.75, halo optional) |

### 5.3 Noise (generated by us, no assets)

- **Base shape:** 128³ RGBA8, tileable.
  - R: Perlin–Worley (Perlin fbm remapped by Worley, Schneider 2015);
  - G, B, A: Worley fbm at increasing frequencies.
- **Detail:** 32³ RGB8 Worley fbm (Schneider 2015).
  - Alternatively, Nubis Cubed's **"alligator" / "curl-alligator" noise** at 128³. Its RG channels give billowy and its
    BA channels wispy detail, mixed by the profile's detail type. The talk and a reimplementation describe this layout.
- **Curl noise:** 128² RG8 for distortion, wisps and turbulence.
- **Blue noise:** a 128² × 64-slice spatiotemporal blue noise (spatiotemporal blue-noise masks after Wolfe et al. 2022,
  generated offline by our own void-and-cluster tool in Java and stored in the repo, 1 MB). It is shared by clouds, fog
  and other techniques.
- **Generation:** a startup compute pass (< 50 ms once, est.), deterministic, so tests can hash it. Total about 8.5 MB
  of GPU memory.

### 5.4 Cirrus and high layers

- **Option 1** (default): a thin volumetric shell (200–500 m thick) at 7–12 km. It is marched with 4–8 steps using 2D
  noise extruded by height and its own weather channel, and lit with single scattering plus one octave. It is cheap and
  gets parallax right for airplanes passing through or below.
- **Option 2:** a 2D layer (textured shell, analytic lighting) for low-end devices. Both are kinds of the cirrus
  sub-setting.

### 5.5 Voxel cache for fly-through (Nubis Cubed, adapted)

- **What Nubis Cubed did** (SIGGRAPH 2023 Advances; Guerrilla's abstract; reimplementation notes):
  - replaced the 2.5D model with voxel "NVDF" fields: dimensional profile, detail type and density scale, about
    512×512×64 per field, plus a compressed SDF for skipping empty space;
  - added a 256×256×32 precomputed light (sun optical depth) grid, reported by the reimplementation to save 30–40 %;
  - used detail noise to up-resolution the voxels;
  - built the clouds by fluid simulation in Houdini.
- **Our adaptation (no offline Houdini; the game has to change weather at runtime).** A camera-centred clipmap of
  3D textures, refreshed from the procedural model:
  - **Profile volume:** about 256×256×64 per level (R8G8B8A8: profile density, detail type, density scale, droplet and
    darkness). Two or three levels: e.g. 50 m texels over 12.8 km, 200 m over 51 km. A setting.
  - **SDF volume:** R8 (or R16F) distance to the nearest non-zero density, by jump flooding after each refresh. It skips
    empty space in long steps and is the reason fly-through stays affordable.
  - **Sun optical-depth volume:** R16F, a separable sweep along the sun direction (a march per column in light space).
    It replaces the 6-tap light cone march near the camera. It is recomputed when the sun or the weather moves,
    time-sliced.
  - **Refresh:**
    - by scrolling: write only the new slabs;
    - by weather change: dirty bricks.
    - The budget is N bricks per frame (a setting) on async compute.
  - **Stamps:** optional authored voxel clouds (our own `.nvdf`-like format, produced by an engine tool from a mesh or
    from a simple fluid simulation offline) are composited into the cache. They are for a hero cumulonimbus or a
    "cloud canyon" level. The format and tool are a later stage (V10).
- **Why not voxels only.** A full-sky voxel field to the horizon at useful resolution does not fit. Far clouds stay
  procedural (2.5D, sampled from the weather map); the cache covers where the camera can be close. The marcher reads
  the cache inside its extent and the procedural model outside it. Both evaluate the same density function, so the
  seam is invisible.
- **Memory (est.):** 3 levels × (256²×64 × 4 B + 1 B + 2 B) ≈ 3 × 29 MB ≈ 88 MB. The setting `clouds.cache.levels` and
  the resolution scale it down. Off on low-end devices: the 2.5D path alone still works inside clouds, just slower and
  without SDF skipping.

## 6. Cloud lighting

### 6.1 Direct sun and moon

- **Per sample:** σs × phase(θ) × T_sun × E_sun + multiple-scattering octaves.
- **T_sun near the camera** (inside the cache): one fetch of the sun optical-depth volume plus a short local march of
  2–3 steps for detail-scale self-shadowing.
- **T_sun far:** Schneider's cone march (6 samples in a cone, plus one long sample) on the low-detail density, or the
  low-resolution voxel level.
- **Atmosphere transmittance** applied per sample (sunsets light cloud bases red while the tops are still yellow). This
  is Hillaire 2020's "per-step transmittance" option; one LUT fetch per sample, or per cloud slab as the cheap option.
- **Phase:** Jendersie–d'Eon at the profile's droplet diameter (default 10–20 µm, larger in storms). The dual-lobe HG
  kind is kept for comparison.

### 6.2 Multiple scattering

- **Default:** Wrenninge octaves, N = 3, with (a, b, c) fitted per droplet size to the path tracer (§10.3).
  - Shipped by Frostbite 2016 and UE 2020, shown by Hillaire against a path-traced Moana cloud.
  - It reproduces silver linings (the forward-peaked first octave), bright interiors and dark bases (optical depth).
- **Powder effect** (Schneider 2015's "Beer–powder", `1 − e^{−2d}`): dark edges where the cloud faces the sun. Hillaire
  2020 notes it is not physically based; correct dark edges come from low in-scattering probability at thin edges,
  which octaves only partly capture. Two options:
  - (a) the powder term as a fitted correction, kept only if fitting to the path tracer improves the error;
  - (b) Hillaire's lower albedo at low density, also only if fitted.

  Both are settings, off unless they reduce the error against the reference. Whether an *art* override may exceed the
  physical fit is a question (§12).
- **Alternatives to benchmark later:**
  - A **multiple-scattering transfer LUT** indexed by (sun optical depth, view–sun angle, local density), precomputed
    from the path tracer on canonical slabs, in the spirit of Bouthors 2008. It may beat octaves on storm interiors.
  - **Neural** (Kallweit et al. 2017 "Deep Scattering"; Hu et al. SIGGRAPH 2023): small MLPs predicting
    higher-order scattering from a density stencil. Practical without libraries only as a tiny MLP evaluated in Slang
    with weights trained offline by our own Java trainer. It is research-grade (D-later); listed, not planned.

### 6.3 Ambient (sky and ground)

- **Sky irradiance** from the sky capture's SH (already computed by `EnvironmentLighting`) or the sky-view LUT. Per
  sample it is attenuated by an estimate of the optical depth *upwards*:
  - inside the cache: a fetch from the profile volume's coarsest mip along +Y;
  - elsewhere: the height fraction in the layer and the profile, as Schneider and Hillaire 2016 do (top light, bottom
    light).
- **Ground bounce:** the ground albedo times sun irradiance times cloud shadow, from below, attenuated the same way
  downward. This is UE's optional "secondary trace towards the ground" in a cheap form. It matters for the undersides
  of clouds over snow, desert or sea.
- **Fitted** with the octaves to the path tracer: ambient is where cheap models are most wrong.

### 6.4 Shadows inside clouds

These are covered by §6.1 (self-shadowing). Shadows *from* terrain or the airplane onto clouds are a minor effect (a
mountain shadowing a stratus layer at sunset); they would need the sun's shadow cascades sampled per cloud sample near
the ground. That is a setting, off by default.

### 6.5 Lightning

- **A lightning event** (game API: `Weather.lightning(position, intensity, duration)`, or automatic within storm cells
  at a rate that is a setting) creates:
  1. **In-cloud glow:** the bolt is a polyline (generated by a midpoint-displacement algorithm) inside the cloud. In
     the marcher, each sample adds `Le × σs × phase × f(r, τ̄)` from the nearest bolt segment, where f is a diffusion
     falloff `e^{−σ_eff·r} / (4π·D·r)` with σ_eff from the local density (Dobashi et al.'s observation that multiple
     scattering dominates lightning-lit clouds). The falloff is fitted against the path tracer.

     Cost: a segment-distance computation per sample while a flash is active.
  2. **An engine light** (a point or line light in `Lights`, intensity from the same flicker curve) for the ground,
     the fog and the scene. Shadowed via #120 if budget allows.
  3. Optionally a **visible bolt** (emissive ribbon, bloom), only if the user wants it (§12).
- **Flicker envelope:** a few return strokes over about 0.2–0.5 s.
- **Rendering:** the cloud temporal accumulation must react within one frame. The history weight drops while a flash
  is active (an exposure-change flag); the same goes for the froxel fog history.
- **Nubis (GDC 2022, "Real-Time Volumetric Superstorms")** reports near-zero-cost internal lighting and lightning in
  the same family of renderer. The slides are not public in text, so our method is our own, validated against the path
  tracer.

## 7. Cloud shadows (ground, fog, atmosphere, #120)

### 7.1 Beer shadow map

- Hillaire 2020 (UE). An orthographic map from the sun, centred on the camera and texel-snapped, R11G11B10F:
  - front depth z;
  - mean extinction behind the front;
  - maximum optical depth.

  Transmittance at depth d is `exp(−min(B, G·max(0, d − R)))`. It suits media of varying density better than an
  exponential shadow map (ESM shadows darken wrongly with distance from the layer, as the slides show), and needs no
  Fourier or transmittance-curve coefficients.
- **Size:** 1024² over 32 km (31 m texels) by default, plus a 256² far level over 200 km. Both are settings.
- **Update:** marched with 16–32 steps per texel, time-sliced (a quarter of the map per frame). It moves with the
  weather and wind continuously by applying the wind offset to lookups between updates.
- **Est. cost:** 0.1–0.2 ms per frame on async compute.
- **Filtering:** a bilateral blur of the extinction and optical-depth channels with the front depth untouched (as
  Hillaire suggests).

### 7.2 Into #120 (shadows as data)

- The sun's visibility in shading becomes `shadow(sun) × cloudTransmittance(x)`. Because cloud transmittance is a
  property of the light, not a shadow method, the proposal is a **per-light transmittance term** in the shadow table:
  - flag `CLOUD_TRANSMITTANCE`;
  - the Beer map's slot;
  - its matrix.

  The `Shadows` owner fills it in for the directional light the atmosphere calls the sun. Every shading path,
  transparents, particles, froxel fog, GI hit shading and the path tracer read it through the same helper as the shadow
  itself.
- **Alternative:** #120's "shadow-mask" plugin path (a screen-space mask per light). It is rejected as the main route:
  the fog, GI hits and transparents are not on the screen grid. It is fine as the fallback if #120 does not take the
  term.

### 7.3 In fog and atmosphere

- Froxel fog samples the Beer map per froxel (sun shafts through cloud gaps).
- AP and sky-view sample it per sample (§4).
- The per-pixel atmosphere option gives sharp shafts at kilometre scale.

### 7.4 Cheap fallback

A 2D coverage projection (weather map coverage × profile thickness, along the sun) is used when clouds are off or on
low-end devices. It needs no marching.

## 8. Volumetric fog (froxels) — #419

### 8.1 Grid

- **Size:**
  - Screen tiles of 8 px (default at 1080p, giving 240×135) or 16 px (a setting), with 128 depth slices (64 on
    low-end devices).
  - Distribution: exponential in depth from 0.1 m to `fog.far` (default 300 m; a setting up to 2 km).
  - A near "linear" region keeps slice thickness ≥ 0.25 m.
  - The tile size is relative to the render size; at 4K the default is 16 px → 240×135, the same grid.
- **References:**
  - Wronski 2014 (AC4: 160×90×64, about 1.1 ms total on Xbox One, as reported in coverage of the talk);
  - Hillaire 2015 (froxels aligned with the light tiles, RGBA16F scattering + extinction, one sample per froxel);
  - Unreal (16 or 8 px tiles, 64–128 slices, strong temporal reprojection with sub-voxel jitter);
  - Godot 4 (64×64×64 by default, compute with atomics for fog volumes).
- **Formats:**
  - V-buffer A: scattering RGB + extinction (RGBA16F);
  - V-buffer B: emission RGB + phase g (RGBA16F);
  - lit scattering (RGBA16F, two for history);
  - integrated (in-scatter RGB + transmittance, RGBA16F).
- **Memory:** 240×135×128 × 8 B × 5 ≈ 166 MB at 128 slices. **That is too much**, so the defaults are:
  - lighting and history at 160×90×128 (≈ 74 MB for 5 volumes; 2 eyes → 148 MB);
  - or R11G11B10 lighting with transmittance in a separate R16 volume (≈ 46 MB).

  The final grid, and its tradeoff against memory, is decided by the benchmark (§10.4). Stereo doubles it (per-eye
  layers).

### 8.2 Media sources (inject pass)

- **Global:** the atmosphere (Rayleigh, Mie, ozone near the ground) and height fog (exponential, with its own albedo and
  phase). The fog's phase is the Jendersie–d'Eon droplet fit for water fog, or HG for dust.
- **Local fog volumes** (scene data: box, sphere, ellipsoid, cylinder, with an edge falloff):
  - density, albedo, emission and phase;
  - optional 3D noise (the cloud noise textures) with a wind scroll;
  - optional authored 3D textures (a `FogVolumeData` scene type).
  - Culled to froxel tiles by a compute pass (bounded list per tile), evaluated per froxel.
  - Negative density allowed (clearing fog in a room), as Godot does.
- **Particles** (smoke, dust, steam, fire glow):
  - A particle module `media` makes a particle splat its density footprint (a sphere with a falloff) into a
    **media-injection volume** with atomics on fixed point; a cheaper gather from a per-tile particle list is the
    alternative to benchmark.
  - Emission (fire) goes in V-buffer B.
  - Hillaire 2015 injected particles into the froxels the same way, and also built particle volumetric shadows (§8.3).
- **Clouds near the camera** (unified, as Bauer 2019 (RDR2) does with clouds and fog in one march):
  - When the camera is in or near clouds (a cache level covers the froxel range), the inject pass also adds cloud
    density from the voxel cache.
  - Local lights (landing lights, lightning, a burning wreck) then light the cloud near the camera through the froxel
    path, and the cloud marcher starts at `fog.far` (§9.3).
  - This is a setting (`clouds.froxelNear`) and is benchmarked against marching everything in the cloud pass.

### 8.3 Lighting (light pass), per froxel, jittered within the froxel

- **Sun and moon:**
  - shadow from #120's cascades (one bilinear PCF tap);
  - × the cloud Beer shadow map;
  - × atmosphere transmittance;
  - × phase.
- **Local lights:** the clustered light lists (`ClusteredLights`), with the froxel's slice mapped to the cluster's
  Z-slice. Each light gets the phase, its falloff, and a **shadow from #120**:
  - shadow-map lights: one tap from the atlas tile, cube face or cascade;
  - **ray-traced-shadow lights**: their screen masks don't apply to froxels. The default is a **stochastic ray query**:
    each froxel picks K lights per frame by importance (K = 1–2, a setting), traces one shadow ray each, weights by
    1/p, and the temporal pass accumulates (in the spirit of MegaLights / ReSTIR). The alternative is a small shadow
    map rendered for fog only for such lights. Benchmark both.
- **Ambient:**
  - GI probe volume irradiance at the froxel, through `diffuseLightAt` with an isotropic phase; SH-L1 for anisotropic
    phase (small gain, a setting);
  - multiplied by the probe's sky visibility for sky light, so fog in a room is not lit by the sky.
  - Without probes: the sky SH × an analytic sky visibility of 1 (outdoors).
- **Volumetric shadows within the fog itself** (fog shadowing fog), and particle smoke shadowing the scene:
  - an **extinction volume in light space** (Hillaire 2015's particle volumetric shadow maps; Unreal's "volumetric
    shadow" for local lights) is a later option (V9);
  - for the sun, the froxel integration already shadows the view ray, but not the light ray. A sun-space extinction
    clipmap (64×64×32) can supply it.
- **Emission** adds directly.

### 8.4 Temporal

- **Jitter:** the sample position within each froxel follows the blue-noise sequence per frame.
- **Reprojection:** the previous frame's lit volume, using the previous view-projection (from the view constants).
- **Blend:** 0.9 history by default (a setting).
- **Rejection:**
  - history outside the previous frustum is rejected;
  - a light that changed (#120 / `Lights` version), or a lightning flash, drops the history weight for affected
    froxels (GI design D3's responsiveness rules: ≤ 4 frames to 90 % for known changes);
  - neighbourhood clamping in froxel space is a setting (Unreal's documented ghosting trade-off).
- **One frame of latency:** none in the image; history only smooths.

### 8.5 Integration and apply

- **Integration:** front to back along each froxel column with the energy-conserving form, producing
  (in-scatter, transmittance) per froxel. The aerial perspective is re-based at `fog.far` (§4).
- **Apply to opaque:** one fetch at the pixel's depth (tricubic or a blue-noise-jittered trilinear to hide slices).
  `color = color × T + L_in`.
- **Transparents and particles:** the same fetch in their shader, at their depth. Forward shading and the
  visibility-buffer blended path both use the helper `applyMedia(color, positionWS)`.
- **Volumetric lights reflected by SSR or RT reflections:** reflections see the media at the reflected point only
  through AP (accepted limitation, as in other engines).

### 8.6 Cost

- **Literature:** AC4 about 1.1 ms on Xbox One (≈1.3 TFLOPS); Godot defaults run on integrated GPUs.
- **Est. here** (160×90×128, sun + 50 clustered lights + probe ambient):
  - 1080p: 0.3–0.6 ms;
  - 4K: the same grid, so about the same plus the apply (≈ +0.1 ms);
  - XR: × 2 (per eye) unless the union-frustum option wins (§9.5);
  - stochastic RT shadows add about 0.1–0.3 ms per ray per froxel.

### 8.7 High-quality ray-marched fog — kind `raymarch`

- **Per pixel** at half resolution (a setting), 32–96 steps with blue-noise offsets.
- Same media and lighting functions. Shadows from shadow maps at full resolution, or **ray queries** for sharp beams.
  Lights are importance-sampled stochastically (1–4 per sample), as in the froxel stochastic mode.
- **Temporal + spatial denoise** with the engine's `Denoiser`, then a depth-aware upsample.
- **Uses:** sharp light beams through blinds, flashlights in smoke, cinematic screenshots, and the near-field reference
  between the froxels and the path tracer.
- **Cost (est.):** 1–3 ms at 1080p, 3–7 ms at 4K. It can be combined: froxels for distant fog, ray-march for the first
  N metres (a later option).

### 8.8 Cheap fallbacks

- **Analytic height fog** with sun in-scatter (no shadows): about 0.02 ms. It is part of the AP apply.
- **Epipolar sampling** (Engelhardt & Dachsbacher, I3D 2010), with Yusov's 1D min–max shadow trees (Intel, 2013):
  - single-scattering sun shafts through the shadow cascades (and the cloud Beer map);
  - samples along epipolar lines from the sun's screen position, refined at depth discontinuities, interpolated;
  - correct for directional single scattering;
  - est. 0.2–0.4 ms at 1080p.

  It is the shafts option when froxels are off (low-end, mobile-class).
- **Screen-space radial blur** (Mitchell, GPU Gems 3, 2007): not correct (light only from on-screen bright pixels, no
  real shadowing). Excluded by the correctness rule unless the user wants it as a stylised option (§12).

## 9. Rendering the clouds

### 9.1 March

- **Far (camera outside the layer):** intersect the ray with the layer's spherical shell. Steps:
  - number and length growing with distance and view elevation (Schneider: 64 steps looking up, 128 at the horizon);
  - a two-speed march: coarse steps with base density until density > 0, then back up one step and switch to fine
    steps (Schneider 2015);
  - inside the cache, SDF sphere tracing replaces the coarse phase.
- **Start offset:** blue-noise jitter per pixel per frame.
- **Early exit:** at transmittance < 0.01 (a setting).
- **Limited by scene depth** (downsampled *max* depth of each quarter-res pixel's 2×2 footprint). Clouds wrap around
  mountains and the airplane.
- **Output:**
  - in-scatter RGB;
  - transmittance;
  - **transmittance-weighted mean depth**, used for reprojection, aerial perspective at the cloud and depth-aware
    upsampling.
- **Aerial perspective** is applied per sample (accurate for 100+ km rays and mountains in front) or at the mean depth
  (cheap); a setting.
- **Near (camera inside or close):**
  - The march starts at the camera; the first `near` metres (setting, 2 km) use fine steps, detail noise, curl
    distortion and the light volume.
  - Beyond, steps grow. With `clouds.froxelNear` on, the first `fog.far` metres come from the froxels instead.
  - **No layer-shell artefacts:** step positions are anchored in world space, not to the shell entry, so the sample
    pattern does not swim when the camera crosses the layer boundary.
  - Density inside thin cloud is fog-like by construction (profile × coverage); wisps come from curl distortion at the
    edges.

### 9.2 Resolution and temporal reprojection (benchmark all three; the user picks the default, §12)

| Kind | Scheme | Source | Trade-off |
|---|---|---|---|
| `quarter` (default) | march every pixel of a half-by-half buffer each frame, jittered; temporal accumulation; depth-aware upsample | Bauer 2019, UE 2020, Unity HDRP (quarter res + temporal) | instant response; slightly softer |
| `sparse16` | full-res buffer, 1 of 16 pixels per 4×4 block marched per frame; the rest reprojected | Schneider & Vos 2015 (HZD, < 2 ms on PS4) | sharp when stable; 16-frame convergence, ghosting on fast motion or fast clouds |
| `full` | every pixel every frame (+ optional temporal) | Nubis Evolved 2022 ("detailed results at 1080p without temporal upscaling") | best, 4× or more cost |

- **Reprojection:**
  - by cloud mean depth (not scene depth) plus the cloud's own wind motion;
  - clamped against a 3×3 neighbourhood in YCoCg;
  - disocclusion where scene depth changed (the airplane moving across clouds).
- **Fast-moving clouds** (superstorms, flight at speed): Nubis 2022 mentions "temporal upscaling" fixes. Our handling:
  - the reprojection includes per-pixel cloud motion (the wind at the mean depth);
  - the history weight falls with the reprojection distance.
- **Upsample to full res:** joint bilateral on depth (scene depth vs the cloud's max-depth footprint). Edges against
  terrain use the 4 nearest quarter-res samples weighted by depth similarity.

### 9.3 Composite order

Sky first, then clouds with AP, then the froxel near segment (which already contains near-camera cloud density when
`clouds.froxelNear` is on). Clouds output premultiplied (in-scatter, transmittance), so
`scene = scene × T_cloud + L_cloud`, then the fog apply.

### 9.4 Cost (literature → est.)

- **Reported:**
  - HZD: < 2 ms on PS4 (≈1.84 TFLOPS) at 1080p with `sparse16`;
  - UE: "trace at quarter resolution + TAA";
  - HDRP: quarter resolution + temporal accumulation (no ms published).
- **Est. on RX 9070 XT, `quarter`:**
  - 1080p (960×540 marched): 0.6–1.2 ms for scattered cumulus; up to 2–4 ms inside a cumulonimbus (long dense
    marches, lightning);
  - 4K (1920×1080 marched): 1.5–3.5 ms.
  - `sparse16` about a quarter of that; `full` about 4×.
- Each stage measures the real numbers with the existing benchmark method (rounds, medians, GPU timestamps).

### 9.5 XR (stereo)

- **Disparity argument.** IPD ≈ 64 mm. At distance r the angular disparity is 0.064/r rad. A 2064-px eye over about
  100° is ≈ 1,180 px/rad, so disparity in pixels ≈ 75 / r[m]: 0.075 px at 1 km, 0.4 px at 200 m.
- **Default (`clouds.stereo = shared-far`):**
  - Clouds beyond `stereo.split` (default 300 m; a setting) are marched **once** from the head centre into a buffer
    covering the union of both eyes' frusta (slightly wider). Each eye resamples it by direction (exact up to
    sub-pixel disparity).
  - The segment from each eye to `stereo.split` is marched per eye (usually empty or short; inside clouds it is the
    expensive, stereo-relevant part).
  - The two composite as two segments of one ray (exact, like the AP re-basing).
- **Alternative (`per-eye`):** both eyes fully, with multiview layers (cost ×2). This is the reference for the shared
  mode's error test.
- **Froxels:** per eye (layers), the default. Alternative: one union-frustum grid from the head centre; benchmarked.
- **AP volume:** per eye. **Sky-view LUT:** shared (the same position up to IPD). **Beer shadow map and voxel cache:**
  frame scope, shared.
- **Temporal:** histories per eye. The shared far buffer has its own history from the head centre.

## 10. Validation: references and tests

### 10.1 Reference path tracer with media (extends `ReferencePathTracer`)

- **Free-flight sampling:**
  - delta tracking with a **majorant grid** (coarse max density per brick, from the cloud cache and the fog volumes);
  - ratio tracking for shadow rays (Novák et al. 2014);
  - spectral tracking for chromatic media (Kutz et al. 2017).
  - The null-scattering formulation (Miller et al. 2019) keeps it unbiased; see the Novák et al. 2018 STAR for the
    full family.
- **Media:**
  - the spherical atmosphere from `media.slang`;
  - height fog, local volumes and clouds from the **same density functions** as the real-time code: the 2.5D model
    and the cache's source, not the cache itself.
- **Phase sampling:** analytic for all kinds (Jendersie–d'Eon give the Draine inversion).
- **Optional spectral mode** (8–16 wavelengths) to measure the RGB error of sunsets.
- **Surface interaction:** the existing BRDFs and lights; sun with atmosphere transmittance; the sky as an emitter
  (path-traced atmosphere, not the LUT).
- **Progressive accumulation** as today.

### 10.2 Closed-form tests (no image comparison needed)

- Phase functions integrate to 1 (Monte Carlo over the sphere, 1e-3). Sampling matches evaluation (χ² test).
- Transmittance LUT vs direct numerical integration (1e-3 relative).
- Homogeneous slab, single scattering, sun at an angle: analytic result vs the froxel and the ray march (≤ 1 % at the
  default grid).
- **Media furnace:** an infinite medium of albedo 1, uniform illumination → radiance equals the illumination
  (path tracer). The octave model with its fitted parameters is tested for energy ≤ 1.
- Energy-conserving segment integration vs a fine reference march as Δ → large.
- Aerial-perspective re-basing: froxel [0, f] ⊕ AP [f, d] equals AP [0, d] for the atmosphere-only medium.
- Stereo shared-far composite equals per-eye within 0.5 px disparity (max-error image test).

### 10.3 Image comparisons and fitting

- **Atmosphere:** sky-view vs the path-traced atmosphere at 12 sun angles × 3 altitudes (0, 10 km, 100 km). Bruneton
  2008 (our port) as a second reference. Error budget: relative luminance error ≤ 3 %, hue shift reported.
- **Clouds (canonical scenes):**
  - a cumulus from our generator;
  - a stratus slab;
  - a cumulonimbus with anvil;
  - a cloud sphere (Hillaire-style);
  - each at sunrise, noon and backlit, and from inside.
- **Fitting:** a Java optimiser (Nelder–Mead, no library) fits:
  - (a, b, c) of the octaves;
  - the ambient attenuation;
  - the lightning falloff;
  - the optional powder or albedo correction,

  minimising the error to the path tracer over these scenes. The fitted values ship as defaults (still settings).
  Fitting reruns are a test task.
- **Fog:** the issue's screenshots, each with a path-traced reference:
  - a dusty room with sun shafts;
  - smoke past a window;
  - a spot light in fog;
  - fog over terrain.
- **Metric:** per-region relative error plus a perceptual error. FLIP (Andersson et al. 2020) is ported to Java/Slang
  from the paper, if the GI work hasn't already.

### 10.4 Benchmarks

- **Method:** the existing one (`*Benchmark`, `TRUESIM_BENCHMARK`, `TRUESIM_SCREENSHOTS`, GPU timestamps per pass).
- **Resolutions:** 1080p, 4K, and XR (2064×2208 per eye).
- **Scenes:**
  - clear;
  - scattered cumulus;
  - overcast;
  - storm with lightning;
  - fly-through (scripted path into and through a cumulonimbus);
  - sunset;
  - fog with 1, 50 and 500 lights.

## 12. Decisions for the user (taste; one at a time, recommendation first)

1. **Physical vs art-directed clouds.** Should clouds be strictly fitted to the path tracer, or may artists push beyond
   it?
   - (a) **Physically fitted only**: powder and edge-albedo only where they reduce error. *Recommended*: matches the
     rules.
   - (b) Physical defaults plus art overrides (powder strength, silver-lining boost, darkness), off by default.
   - (c) Art-first, Nubis-style tuning.
2. **World scale.** How high and far does the camera go?
   - (a) **Ground to about 15 km** (airplanes): 64 km weather map, far map to 400 km. *Recommended*.
   - (b) Ground only (≤ 1 km): smaller cache, no far map.
   - (c) Orbit and space: planet view, a weather map in planet UVs (cube-sphere), much larger effort.
3. **How weather changes.**
   - (a) **Presets with transitions plus game-placed brushes** (storms rolling in, wind advection). *Recommended*.
   - (b) Plus a lightweight simulation (cell growth and decay, cumulus life cycles of 10–30 min).
   - (c) Real weather data import (METAR/GRIB-like), as flight sims do.
4. **Cloud motion.**
   - (a) **Wind advection plus slow noise evolution**. *Recommended*.
   - (b) Plus visible billowing (time-varying noise warping, more cost).
   - (c) Fluid-simulated hero clouds near the player (research).
5. **Default temporal scheme for clouds**: (a) **quarter + temporal** (instant, softer). *Recommended*. (b) sparse16
   (sharper, ghosting at speed). (c) Full (4× cost). All three are built and benchmarked; this sets the default.
6. **Fly-through priority.**
   - (a) **Voxel cache from V7**: best inside-cloud quality and lighting. *Recommended* if the airplane matters.
   - (b) Layered only, near detail without a cache: cheaper memory (no ~90 MB), slower inside.
7. **Lightning.**
   - (a) **In-cloud flashes plus the scene light**. *Recommended*.
   - (b) Plus visible bolts and ground strikes (ribbon geometry, bloom).
   - (c) Flashes only.
8. **Rain shafts and precipitation under storms** (virga, rain curtains as media below cloud bases): (a) **later stage
   (V9)**. *Recommended*. (b) Not in scope.
9. **Night sky**: (a) **moon plus a star field (a procedural catalogue of bright stars), no airglow**. *Recommended*.
   (b) Plus airglow and the Milky Way (a texture we generate). (c) Moon only.
10. **Screen-space radial god rays**: (a) **drop** (not correct; epipolar covers low-end). *Recommended*. (b) Keep as a
    stylised option.
11. **Colour accuracy**: (a) **RGB with fitted wavelengths, the spectral path tracer measuring the error**.
    *Recommended*. (b) Spectral sky LUTs (4–8 wavelengths, ~2× LUT cost) if sunsets miss the error budget.
12. **Memory ceiling for volumetrics**: (a) **≤ 256 MB at high, ≤ 96 MB at medium**. *Recommended*: cache ~88 MB +
    froxels ~46–148 MB + noise ~9 MB + shadow maps ~8 MB. (b) Other budgets.

**Order rationale.** The atmosphere first: it gives the engine a real sky and sun colour, feeds GI and the
environment, and is the cheapest high-value step. Fog before clouds: smaller, and it builds the shared media, temporal
and shadow plumbing that clouds reuse. Fly-through after the far clouds are right and fitted, because the cache
accelerates a correct model rather than defining it.

**External dependencies:**
- #120 shadows: the cascades and atlas for V3 and V4, and the transmittance term for V6. Until then, V3 uses today's
  `CascadedShadowMaps`.
- Frame graph 3D images, histories and shared requests: phases done per the design doc.
- TAA #403: not required (clouds and fog have their own temporal passes), but final quality is judged with TAA on.

## 14. Risks

- **Temporal artefacts** (ghosting of clouds over moving airplanes and terrain edges; fog trails behind moving lights):
  - reprojection on cloud depth plus disocclusion masks;
  - history rejection by light versions;
  - tests with scripted motion.
- **Fitting may not reach the error budget** for storm interiors with octaves alone. V11's transfer LUT is the planned
  fallback, and the report will say so with numbers rather than tune by eye.
- **Memory of froxels at 128 slices with stereo** (up to ~150 MB). R11G11B10 packing and the union-frustum option are
  the mitigations; 64 slices on medium.
- **Stochastic RT shadows in fog** are noisy for many overlapping lights; the shadow-map-for-fog alternative is built
  alongside (benchmark rule).
- **Shell seams:**
  - between the voxel cache and the procedural far field: the same density function, tested with an image diff across
    the boundary;
  - between the froxel near segment and the cloud march: exact segment composition, tested.
- **The Nubis Cubed slides could not be read in full here** (the PDF exceeds the fetch limit). Their details (NVDF
  channels, light grid size, alligator noise) come from Guerrilla's abstract and a published reimplementation. Read
  the slides before V7.

## User decisions (2026-11-06)
1. Clouds: physically fitted defaults plus art overrides, off by default.
2. Range: ground up to orbit (planet view; per-pixel atmosphere path for space, clouds over the planet).
3. Weather: presets with transitions + game brushes + a storm life-cycle simulation (deterministic, for multiplayer).
4. Cloud motion: wind + slow evolution, visible billowing, and fluid-simulated hero clouds (all as choices).
5. Temporal schemes, resolutions, memory budgets: all adjustable settings (defaults from benchmarks).
6. Lightning: everything (in-cloud flashes, scene light, visible branching bolts, ground strikes), bolts maybe via scene's effects library.
7. Night sky: configurable, "implement the real deal": moon with phases, real star catalogue (licence checked), airglow, Milky Way.
8. Layout: new repository true-sim/environment (data/simulation modules without the engine, render techniques as registry plugins); the engine gets as little as required (generic hooks only: Environment source, shadow-table transmittance, fog lookup in shading).
Lead's calls by the user's rules (configurable, real deal): rain shafts in; spectral sky tables as an option next to RGB; screen-space radial god rays only as a labelled stylised option, off.
9. Quality tiers (user, 2026-11-06): every component offers cheaper techniques for games not aiming at realism —
   technique-registry kinds plus low/medium/high/ultra presets, all individually overridable. E.g. atmosphere: LUT
   model / analytic sky (labelled approximate) / gradient; clouds: voxel fly-through / layered ray-marched / 2D or
   billboard / none; weather: storm life cycle / presets only / static; stars: catalogue / procedural / texture; fog:
   froxels / ray-marched HQ / analytic height fog / off; lightning: full / flashes only. Data and simulation serve
   every tier; cheap tiers never need the expensive data.
